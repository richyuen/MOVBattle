# Improvement loop v4: one iteration

You are the worker. Make each MOVBattle unit look and operate like its TABS original, one batch of units at a time (a faction, or
a slice of a big one). An adversarial critic judges your work against the unit's wiki card and renders; you never judge it yourself.
Per iteration: up to 7 structural gaps across the batch's open units, implemented in sub-batches with one look each, then one
capture, one critic review, verdicts (a second critic confirms a unit before it is done), memory. No regression suite except the batch
checkpoint. Follow the steps in order.

## 0. Preflight
- `git branch --show-current` must print `main`. `git status --porcelain` must be empty. No file named `STOP` in the repo root. `node loop/scripts/budget.mjs` must pass.
- On any failure: end the turn with one line saying why, no commit (the autoloop stops on a turn without a commit).
- Tooling: write source and memory files with the Write and Edit tools (Bash heredocs eat backslashes); commit messages via a file and `git commit -F`; never `git commit -a`. Probes (`loop/scripts/probes/`, listed in LESSONS) run from the repo root, `--build` after a source change.

## 1. Load memory (and nothing else)
- Read `loop/STATE.md`, `loop/LEDGER.md`, `loop/LESSONS.md`. The batch is STATE's `Batch:` field. Read `loop/units/<id>.md` for every unit of the batch that is not `D` (done) or `p` (parked) in the Scoreboard; a unit with no file is unaudited.
- Read a unit's card `loop/cards/<id>.md` only when you pick a gap on it. Never read `loop/archive/`, cards or unit files outside the batch, `progress.md`, `.omx/`, `web/*.md`, `output/loop/*/full-state.json`, or a source file over 20 KB in full (Grep and ranged reads). Never write to the auto-memory directory.
- N = Iteration in STATE + 1. If the Scoreboard has no open or queued unit left: write the reason into a file named `STOP` and end the turn.

## 2. Batch audit (when the batch has unaudited units, or STATE Notes orders a re-audit)
- `node loop/scripts/capture.mjs --iter N --batch <batch>` (foreground, 10 min timeout): every unit's shot set and `lineup_<faction>` into `output/loop/iter-N/`. Read only `summary.json`: its `notes` say what each unit's sim recorded (`release = ... at ... ms`, `ability ...`, or `nothing within 9 s`).
- Re-audits. An evidence commit that changes the camera of a shot re-opens that shot's criteria for the batch's open units: the next step 2 is a RE-AUDIT of those criteria only (say so in the critic prompt and give it each unit file's Verdicts block; the other criteria keep their verdicts). `<faction>:re` batches are retired (the CONFIRM critic in step 7 replaces them); `farmer:re` finishes as it is.
- Tail overlap: at step 3, when the batch has fewer than 5 pickable `[S]` and the next batch is unaudited, run this step for the next batch now and pick from both; `Batch:` names both (`medieval+ancient`) until the first's checkpoint.
- `node loop/scripts/stats.mjs --batch <batch> --iter N`. If it prints an `apply` list, set exactly those values on those units in `rosterManifest.ts` (the entry's `cost` number and the options `healthMultiplier`, `damageMultiplier`, `cooldownMultiplier`; nothing else), type-check, then `node loop/scripts/capture.mjs --units <first unit of the batch>` (refreshes `output/loop/ours.json`; health follows cost) and rerun stats with `--iter N`; if it prints a second `apply` list (health moved with the cost), set those too and repeat once. Commit alone as `loop(N.0): [P] <batch> stats`. No critic for this commit.
- Spawn one fresh `Agent` (general-purpose, default model) in AUDIT mode. Its prompt lists, by path: `loop/CRITIC.md`, `loop/LEDGER.md`, every card `loop/cards/<id>.md` of the batch, their images in `reference/units/` (`<id>.red.png`, `<id>.blue.png`, the action shot when there is one), `reference/factions/<faction>.jpg`, `loop/REFERENCE_DIGEST.md` section 2, every PNG in `output/loop/iter-N/`, `summary.json`, `stats.json`. Say it is an AUDIT of the listed units and nothing about what you expect.
- Write each unit's file from the answer (template in STATE's header comment): Verdicts with blockers, Ranked gaps (the critic's entries for that unit). A unit with a-d all PASS is proposed done: it is `D` (`Done: N`) only after the CONFIRM critic of step 7 agrees. Update the Scoreboard.

## 3. Pick gaps: structural first
- A gap is `[S]` structural (adds or replaces a mechanism: a prop mesh, a hair or cloth chunk, a pose, an attack or ability behaviour, an effect; up to 3 files and 300 changed lines, one failing criterion of one unit) or `[P]` polish (constants, colours, sizes; up to 2 files and 20 lines). `[R]` rebuild is the escalation for a criterion marked `plateau` in its unit file: one commit that replaces the mechanism owning the criterion and aims at its whole blocker list, up to 5 files and 600 lines, designed from a spec written at the head of the rewritten mechanism (proportions, shapes, counts read off the renders and the card), approved on one cleared blocker with no regression. At most one `[R]` per iteration.
- Pickable: attempts under 2 (the unit file's Attempts), not spent in LEDGER, its criterion not `plateau` (then `[R]` only) nor `parked`. Take up to 7 pickable `[S]` from the batch's ranked gaps (every open unit file's Ranked gaps, best first across units), at most 2 per unit and on different criteria of that unit, each clearing a numbered blocker; when fewer than 5 are pickable under those limits, a second `[S]` on the same criterion of a unit is allowed if it clears a different blocker. Then at most 1 `[P]`, only one the critic listed as fallout of an `[S]` approved on the same unit within the last 3 iterations (Structural attempts in LEDGER), whose NEXT line names the shot it shows in.
- Starvation: an open FAIL criterion with no attempt in the last 5 iterations (the unit file's Attempts) is picked this iteration and takes one of the 7 slots, from its Ranked gaps or, when the critic listed none for it, the first blocker of its list. A starving `plateau` criterion's `[R]` takes the iteration's `[R]` slot ahead of any other.
- Evidence first: a blocker whose named shot cannot show its element (the critic said so, or a ranked gap or STATE note says "evidence commit first") is re-aimed before any pick on that unit, outside the 7 slots: edit `loop/scripts/capture.mjs` (the unit scene, a camera rule) and commit it alone as `loop(N.0): evidence - <what>`; rewrite the blocker's shot in the unit file. Shots must stay deterministic (time through `window.advanceTime` only, `Math.random` seeded by capture.mjs).
- Read the unit's card, its Rejected lines and the LEDGER rows for every identifier you intend to touch; for a gap on a or b, look at `reference/units/<id>.red.png` (and the action shot when there is one) before writing geometry. Write the picks into STATE's Focus. Record `BASE=$(git rev-parse HEAD)`.

## 4. Implement in sub-batches, one commit per gap
Work the picks in ranked order, two or three at a time. For each gap: make the change that clears its blocker, touching only what it needs; an `[S]` gap must change behaviour or geometry, not only numbers. New cloth, hair, ornament or dress functions go in `web/src/units/<faction>Dress.ts` (create it on the first one, after `tribalDress.ts`), never into `unitFactory.ts` or `propBuilder.ts`; prop and vehicle cuts stay with their family. Type-check with `node web/node_modules/typescript/bin/tsc --noEmit -p web/tsconfig.json`. Commit only that gap: subject `loop(N.k): [S|P|R] <unitId>: <gap>` plus the attribution lines. After each sub-batch but the last, one look: `node loop/scripts/capture.mjs --units <the sub-batch's unit ids>` (a few minutes; writes `output/loop/look/`), and read each gap's named shot: its element must be there and visible. The last sub-batch is looked at in step 5's capture instead (same rule; a revert there is followed by step 5's capture again, with every touched unit, since each run rewrites `summary.json`). A gap whose element is not visible is reverted now (`git revert --no-edit <sha>`) and recorded in its unit file's Attempts as `dropped`; a commit the critic cannot see is a wasted review. At most 2 follow-up commits per gap per iteration (`loop(N.kb)`, `loop(N.kc)`): a gap still wrong after its second follow-up is reverted whole (`dropped`) and the cause goes into LESSONS. Before choosing a material colour, read `output/loop/palette.png` (every unit capture rewrites it) and take the code value whose swatch displays the target; the displayed colour is not the code value. Write each kept sha next to its gap in Focus. In LEDGER: append each `[S]` to Structural attempts, and update one row per tuning knob a commit changed (verdict `pending`, old value kept under earlier values). Add the gap to the unit file's Attempts.

## 5. Capture evidence
`node loop/scripts/capture.mjs --iter N --units <every unit touched this iteration>` in the foreground (10 min timeout). Read only `output/loop/iter-N/summary.json`. A note `shot may miss: ...` or `nothing within 9 s` on a unit whose gap aimed at c, or a non-empty `consoleErrors` or `pageErrors`, is evidence trouble: fix its cause with a follow-up commit on that gap before the critic runs, or revert the gap. If a gap changed a stats knob, `node loop/scripts/stats.mjs <id> --iter N`.

## 6. One critic review
Spawn a fresh `Agent` (general-purpose, default model). Its prompt lists, by path: `loop/CRITIC.md`, `loop/LEDGER.md`, for each touched unit its card, its images in `reference/units/`, the Verdicts block of its unit file (verbatim), `reference/factions/<faction>.jpg`, `loop/REFERENCE_DIGEST.md` section 2, every PNG in `output/loop/iter-N/`, `summary.json`, `stats.json`, and for each gap its tag, unit, sha and `git show --stat <sha>` plus per-file diffs for files under 300 changed lines. For a gap aimed at a colour-only blocker (the blocker names a hue or shade and nothing else), add a swatch: the element close up with `node loop/scripts/probes/probe_close.mjs --build --unit=<id> --aim=... --noglow --out=output/loop/iter-N/unit_<id>_swatch.png`, and say which blocker it is for. State which gaps were attempted and nothing about how well you think they went.

## 7. Apply verdicts
- Each REJECT: `git revert --no-edit <sha>`. If the revert conflicts, `git revert --abort`, keep the code, mark it `rejected-kept`. Record it in the unit file's Attempts and Rejected with attempts+1 and the top defect.
- Set each touched LEDGER row's verdict, and the gap's Structural attempts line, to the critic's verdict. A row attempted twice as `[P]` without approval becomes `spent`.
- Apply the critic's blocker strikes and additions to the unit file's Verdicts. Blockers not struck keep their text verbatim: a critic block that rewords or narrows one is applied as kept, and its reword goes to the unit's Notes only if it says something new. Two mechanical strikes on an APPROVE: a standing blocker on a that the block's LINEUP line does not place in `lineup_<f>` is struck (a LINEUP line missing or reading `n/a` strikes nothing); a blocker joining two elements with "and" whose CLOSER says one clause cleared is split at the "and" and that clause struck (the rest stands verbatim). An added blocker is applied only when its `introduced by <sha> at <file:function>` names a hunk of this iteration's diff; otherwise it goes to the unit's Notes. Count the approved `[S]` since the list was written on the criterion line. A criterion with 2 rejected `[S]` since its list was written, or 3 approved `[S]` in a row on it with no strike among them, is `plateau` (next pick on it is one `[R]`); an `[R]` rejected twice parks the criterion (`parked`, not picked again). A unit is `D` when a, b, c PASS in its file and d PASS in `stats.json`; a unit is `p` when every FAIL criterion it has is parked.
- CONFIRM before `D`: in the iteration a unit would become `D` (this step or step 2's audit), spawn one more fresh `Agent` (general-purpose, default model) in CONFIRM mode on the would-be-done units alone. Its prompt lists, by path: `loop/CRITIC.md`, each unit's card and images in `reference/units/`, `reference/factions/<faction>.jpg`, `loop/REFERENCE_DIGEST.md` section 2, each unit's PNGs and `lineup_<f>` from this iteration's capture, `summary.json`, `stats.json`; it says these units are proposed done and nothing about the first critic's verdicts. A criterion is PASS only when both critics pass it; a criterion the confirmer fails takes the confirmer's blocker list (FAIL, 0 since N) and the unit stays open.
- Consecutive empty: reset to 0 if any gap struck a blocker or flipped a criterion, else +1 (an approval that struck nothing is not progress). At 5, write the reason into a file named `STOP`.

## 8. Batch checkpoint
`Batch:` may name several batches (`farmer:re+ancient`). When this iteration leaves no unit of one named batch open (all `D` or `p`): `node loop/scripts/capture.mjs --iter N --regression-only` once, then drop that name from `Batch:`. The suite is a smoke test, not a fidelity gate: a scenario that errors, hangs or whose battle never ends goes into STATE Notes as the required first commit of the next iteration; a threshold miss is re-baselined in this iteration's docs commit with its cause named. When `Batch:` would be empty, advance it to the next name in STATE's batch list; its units are unaudited (step 2 next iteration). Never run the suite at any other time.

## 9. Write memory and commit
- Rewrite every touched `loop/units/<id>.md` (cap 3200 bytes: Verdicts, Ranked gaps left, Attempts, Rejected last 4, Notes max 3 lines). Attempts older than 10 iterations compact to one range line per criterion (`339-391 | ... | a | approved`).
- In LEDGER drop Structural attempts older than 5 iterations and rows untouched for 25.
- Append to `loop/LESSONS.md` (one line under its heading) anything learned this iteration that is not about one unit: a rendering or capture behaviour, a probe, a camera rule, a pattern that failed twice. Near its cap, merge duplicates and drop lessons that are now comments at the code they describe.
- Rewrite `loop/STATE.md` fully: Iteration N, Batch, counters, Scoreboard (every unit's a-d marks and status), Focus with shas and verdicts ending in `- <approved>/<total>, <struck> struck`, Last verdicts (critic header lines verbatim), Notes (max 5 lines).
- `node loop/scripts/budget.mjs` must pass. Commit the docs: subject `loop(N): <batch> <approved>/<total> gaps approved`.
- `git push` (bare, no arguments). If it fails, note it in STATE Notes and carry on; the commit is what counts.
- End the turn with a two-line summary. Do not ask questions.
